# Events Aggregator

Сервис для работы с мероприятиями через Events Provider API. Сохраняет мероприятия в PostgreSQL и обновляет данные раз в сутки. Позволяет просматривать события и свободные места, регистрироваться на мероприятия и отменять регистрацию.

Стек: Python 3.12, FastAPI, SQLAlchemy, PostgreSQL, Alembic, Docker.

## Запуск

Для локального запуска нужны Python 3.12, uv и Docker.

Создать .env на основе .env.example и заполнить настройки окружения.

- cp .env.example .env
- uv sync
- docker compose up -d db
- uv run alembic upgrade head
- uv run uvicorn app.main:app --reload

Swagger: http://127.0.0.1:8000/docs

## Регистрация

Для регистрации и отмены используются транзакции PostgreSQL с защитой от параллельных операций. Незавершённые подготовленные операции очищаются автоматически.

При регистрации через POST /api/tickets можно передать idempotency_key в теле запроса.

Повторный успешный запрос с тем же ключом и данными возвращает HTTP 201 и прежний ticket_id без повторной регистрации. Если данные отличаются, сервис возвращает HTTP 409.

При неизвестном результате регистрации возвращается HTTP 503. Перед повторной попыткой необходимо проверить состояние операции.

Срок хранения успешных результатов задаётся через TICKET_IDEMPOTENCY_TTL_HOURS, по умолчанию 24 часа.

## Уведомления

Отправка уведомлений реализована через Transactional Outbox. Билет и событие о регистрации сохраняются в одной транзакции.

Воркер запускается вместе с приложением и отправляет уведомления через Capashino. Идентификатор события используется как ключ идемпотентности уведомления.

При ошибке отправки событие остаётся в outbox для повторной обработки. По умолчанию воркер опрашивает таблицу каждые 30 секунд, размер пачки — 100 событий.

Настройки Capashino и воркера находятся в .env.example. Без ключа Capashino отправка уведомлений отключена.

## Мониторинг

Для отслеживания ошибок используется GlitchTip через Sentry SDK. Мониторинг подключается при запуске приложения, если задана переменная SENTRY_DSN.

## Тестирование

- uv run ruff check .
- uv run ruff format --check .
- uv run python -m pytest -q

Для интеграционных тестов необходимо указать адрес отдельной тестовой базы PostgreSQL в EVENTS_AGGREGATOR_TEST_DATABASE_URL.

## Развёртывание

При отправке изменений в main GitHub Actions проверяет код, запускает тесты, собирает Docker-образ и развёртывает приложение на платформе LMS.
